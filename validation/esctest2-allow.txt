# Which esctest2 tests fesTerm is held to.
#
# esctest2 has 559 test methods and we pass 414 of them; #220 records what is
# deliberately left out. A suite that is mostly red on every run gets
# ignored, so this file is the contract instead: everything listed here must
# pass, and a regression in any of it fails CI.
#
# Entries are Python regexes matched against the full test name
# (`ClassName.test_Method`). A bare class name enables the whole class.
# Individual tests inside an enabled class can be excluded in
# `esctest2-skip.txt`, which requires a reason for each. That file is
# currently empty: every test enabled here runs.
#
# Anything not listed here is not enabled yet, and that is a statement about
# features we have not implemented rather than about tests we are avoiding.
#
# Run it with `scripts/run-esctest2.sh`, or survey the whole suite with
# `scripts/run-esctest2.sh --everything`.

# Colour: the 47 tests in ChangeColorTests, ChangeDynamicColorTests,
# ChangeSpecialColorTests, ResetColorTests and ResetSpecialColorTests stay
# disabled, and they will not move on the strength of the OSC 4/10/11/12
# *query* support added for #222.
#
# Every one of those tests sets a colour and then queries it back, so they
# measure the half fesTerm deliberately does not do. ADR 0036 answers queries
# with the colours the renderer actually paints and ignores sets, because the
# renderer does not read a scheme back at paint time: accepting a set would
# make the next query describe a colour nothing on screen uses. Enabling this
# family means implementing runtime palette changes and the cache
# invalidation they imply, which is #220's remaining colour item.
#
# esctest2 has no query-only colour test, so the query behaviour is pinned by
# exact-byte tests in festerm-core instead.

# Reverse wraparound, DECSET 45. The two CUBTests entries that used to be
# skipped now run. The harness is told `--xterm-reverse-wrap 383` because
# fesTerm implements the semantics xterm settled on in patch 383: the cursor
# climbs only across rows that actually soft-wrapped and stops at the start
# of the logical line, rather than the older behaviour of climbing
# unconditionally onto whatever happens to be above. ADR 0037 records why.

# XtermWinops is deliberately out of scope. Its tests resize, move, raise,
# lower and iconify the window, and report its position in pixels - requests
# that hand a remote program control of a local window. fesTerm does not
# answer them, so the family is not an unfinished phase but a boundary.

# DA, DA2 and DECID report a fixed identity chosen to match the feature set
# fesTerm actually implements, and that identity is pinned by exact-byte
# tests in festerm-core rather than by this suite.
