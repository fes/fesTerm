- **admission epoch** (aka automation epoch, attachment epoch) — Opaque generation on a backend attachment that must be captured and rechecked under the admission gate before disclosure. `crates/festerm-admission/src/lib.rs::AutomationEpoch` → [automation](automation.md)
- **bounded ingest** (aka ingest budget, shared ingest budget) — Per-window time and byte budget that keeps terminal parsing and state mutation responsive while sessions drain. `docs/adr/0079-global-terminal-ingest-budget.md` → [terminal-core](terminal-core.md)
- **cell geometry** (aka cell footprint, leading-cell span) — Renderer-owned physical cell rectangles that define cursor, hit testing, selection, and clipping independent of font shaping. `docs/adr/0012-cell-geometry-owns-ligature-and-fallback-mapping.md` → [terminal-core](terminal-core.md)
- **config revision** — Opaque configuration revision used to detect stale or replayed settings during revalidation and approval checks. `docs/automation-design.md` → [config-secrets](config-secrets.md)
- **controller handoff** (aka handoff, lease transfer) — Atomic transfer of control from one controller instance to another under the same session and generation rules. `docs/automation-design.md` → [automation](automation.md)
- **daemon-owned leases** (aka lease ownership, runtime lease) — Per-session ownership epochs that bind attach, recovery, and cleanup to the active daemon generation and refuse stale takeover. `docs/adr/0084-host-based-dev-tunnels.md` → [sessions](sessions.md)
- **DECSET** (aka CSI mode set, private mode set) — Terminal control sequence that sets and resets modes such as wrapping, cursor keys, or alternate screen behavior. `docs/standards-and-implementation-notes.md` → [terminal-core](terminal-core.md)
- **Dev Tunnel bridge** (aka tunnel bridge, remote bridge) — Separate host-side process that terminates the Dev Tunnel and translates protected tunnel traffic into local daemon APIs. `docs/adr/0053-separate-dev-tunnels-session-bridge.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **Direct2D** (aka native D2D, wgpu D2D) — Supported Windows native terminal composition path that draws into shared GPU surfaces while preserving the UI ownership boundary. `docs/adr/0039-opt-in-direct2d-terminal-composition.md` → [terminal-ui](terminal-ui.md)
- **East Asian width** (aka width policy, emoji width) — Unicode width rules that determine whether a completed grapheme owns one or two terminal cells. `docs/adr/0026-grapheme-width-and-color-emoji-fallback.md` → [terminal-core](terminal-core.md)
- **enrolled HOST** (aka enrolled host, host enrollment) — Per-host owner key enrollment used to authenticate a configured host and pin channel-scoped authority to the same host identity. `docs/adr/0084-host-based-dev-tunnels.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **grapheme** (aka grapheme cluster, UAX 29 cluster) — Completed extended grapheme that owns terminal cells according to Unicode width and remains stable across fragmented UTF-8 input. `docs/adr/0026-grapheme-width-and-color-emoji-fallback.md` → [terminal-core](terminal-core.md)
- **GUI action graph** (aka action graph, workflow graph) — Normative map of user-visible GUI transitions and recovery paths that ties behaviors to the design and validation evidence. `docs/gui-action-graph.md` → [terminal-ui](terminal-ui.md)
- **history recovery** (aka recovery replay, state restore) — Restoring terminal state from a daemon snapshot so reattach has the same buffer, mode, and scrollback as a live session. `docs/adr/0038-sessiond-terminal-recovery-snapshots.md` → [sessions](sessions.md)
- **HOST** (aka host service, host endpoint, host daemon) — Configured host service that exposes authorized session inventory, creation, and attachment routing through Dev Tunnel transport. `docs/adr/0084-host-based-dev-tunnels.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **host key trust** — Saved SSH host fingerprint policy that accepts matching keys silently and requires explicit review for changed keys. `docs/adr/0020-persistent-host-key-trust.md` → [ssh-sftp](ssh-sftp.md)
- **host trust decision** — User response enum for reject, accept once, or persist for host-key verification and SSH trust enforcement. `crates/festerm-ssh/src/lib.rs::HostTrustDecision` → [ssh-sftp](ssh-sftp.md)
- **host-based Dev Tunnel** (aka HOST tunnel, host tunnel) — Remote access flow where a configured host service exposes session inventory and creation over an authenticated Dev Tunnel. `docs/adr/0084-host-based-dev-tunnels.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **Job Object** (aka Windows job, process job) — Windows process tree owner that terminates descendants created by a local PTY session when the session is shut down. `crates/festerm-pty/src/lib.rs::ProcessTree` → [sessions](sessions.md)
- **local PTY** (aka pty worker, local shell pty) — Local child-process terminal that owns a PTY or ConPTY and is managed as one session process tree with shutdown and job ownership. `crates/festerm-pty/src/lib.rs::ProcessTree` → [sessions](sessions.md)
- **native vault** (aka secret store, native secret store, platform keychain, secret boundary) — Platform keychain-backed secret boundary that stores opaque credential references outside configuration and synchronization metadata. `docs/adr/0016-native-secret-store-boundary.md` → [config-secrets](config-secrets.md)
- **owner proof** (aka owner binding, verified owner) — Explicit enrolled-owner evidence proving the configured host identity and scope before remote session creation or grant use. `docs/adr/0084-host-based-dev-tunnels.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **owner-bound host** — Host instance whose identity and session grants are pinned to verified owner binding rather than a guessed hostname or public metadata. `docs/adr/0084-host-based-dev-tunnels.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **primary-screen history** — Ordered logical lines retained above the visible primary screen, used for selection, copy, and resize reflow without losing screen semantics. `docs/adr/0017-bounded-logical-scrollback-and-anchored-viewports.md` → [terminal-core](terminal-core.md)
- **profile hosting** — Host-oriented session sharing where a configured machine exposes or creates sessions through an installed profile-backed host service. `docs/adr/0084-host-based-dev-tunnels.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **publisher authentication** (aka publisher PKI, release signer) — Verified publisher identity and signing checks that gate update, install, and protected cleanup operations before host changes are accepted. `docs/adr/0084-host-based-dev-tunnels.md` → [tunnels-enterprise](tunnels-enterprise.md)
- **recovery mirror** (aka authoritative mirror, daemon mirror) — Daemon-owned terminal snapshot used to restore state after reconnect without replaying side effects. `docs/adr/0038-sessiond-terminal-recovery-snapshots.md` → [sessions](sessions.md)
- **recovery snapshot schema** (aka snapshot version) — Versioned layout for daemon recovery snapshots that validates structure, capacity, and screen-generation invariants before adoption. `docs/adr/0038-sessiond-terminal-recovery-snapshots.md` → [sessions](sessions.md)
- **scrollback** (aka history buffer, retained history) — Primary-screen history retained as logical lines with a configured byte budget and eviction policy. `docs/adr/0017-bounded-logical-scrollback-and-anchored-viewports.md` → [terminal-core](terminal-core.md)
- **scrollback budget** — Configured byte limit that bounds retained logical history and triggers eviction without allowing unbounded terminal accumulation. `docs/adr/0017-bounded-logical-scrollback-and-anchored-viewports.md` → [terminal-core](terminal-core.md)
- **session generation** — Exact live daemon generation that pins session attachment, recovery, and takeover to the same valid runtime instance. `docs/adr/0084-host-based-dev-tunnels.md` → [sessions](sessions.md)
- **session recovery snapshot** (aka recovery snapshot, authoritative snapshot) — Length-bounded serialized terminal state sent before live output so a reattached frontend resumes from the daemon-owned state. `docs/adr/0038-sessiond-terminal-recovery-snapshots.md` → [sessions](sessions.md)
- **sessiond** (aka daemon, local daemon) — Standalone local persistence daemon that keeps one PTY alive across frontend exits and exposes a local IPC surface. `docs/adr/0025-native-local-session-persistence-daemon.md` → [sessions](sessions.md)
- **SFTP** — SSH-backed file transfer and remote read/write operations used for GUI file manager and terminal-session file access. `docs/adr/0029-gui-sftp-file-manager.md` → [ssh-sftp](ssh-sftp.md)
- **synthetic backend** (aka backend shim, virtual backend) — Session backend that presents a typed terminal surface without directly owning the underlying shell process or transport. `docs/automation-design.md` → [automation](automation.md)
- **terminal core** — Terminal state machine that owns parsing, cell geometry, resize behavior, and command semantics without depending on GUI or platform pixels. `ARCHITECTURE.md` → [terminal-core](terminal-core.md)
- **terminal flow** — Ordered session event pumping path from PTY output and backend replies through the app and renderer without leaking session I/O into UI code. `docs/mobile-layout-design.md` → [sessions](sessions.md)
- **terminal_replies_owned_by_backend** (aka backend-owned replies, terminal reply ownership) — Backend owns terminal protocol replies generated while parsing output instead of the frontend terminal. `crates/festerm-session/src/lib.rs::terminal_replies_owned_by_backend` → [sessions](sessions.md)
- **traceability** (aka validation trace, machine-check trace) — Machine-checked mapping from changes to required tests and evidence so user-visible behavior remains tied to its source and review. `validation/README.md` → [automation](automation.md)
- **WARP** (aka Microsoft WARP, DX12 WARP) — CPU-backed WARP adapter path used as the supported default for native terminal composition on eligible Windows x64 targets. `docs/adr/0039-opt-in-direct2d-terminal-composition.md` → [desktop-platform](desktop-platform.md)
- **workflow bundles** (aka bundle workflow, automation bundle) — Approved workflow payloads that bind immutable manifests, scopes, and target references before execution. `docs/automation-design.md` → [automation](automation.md)
